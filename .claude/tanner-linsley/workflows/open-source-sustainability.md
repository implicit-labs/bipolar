# Open Source Sustainability

Based on Tanner Linsley's approach to funding TanStack, managing community, and avoiding maintainer burnout. The philosophy: treat open source like a business — with revenue, support, and boundaries.

---

## Steps

### 1. Build from Genuine Need
Start every library from a real production problem at your company. This creates symbiotic value: the community gets battle-tested tools, your company gets solidified features. Don't build for theoretical elegance.

### 2. Fund Through Partnerships, Not VC
Strategic partnerships (Cloudflare, AG Grid, CodeRabbit) provide sustainable funding without investor pressure. GitHub Sponsors and ad placement supplement. No paid versions, no enterprise tiers — keep it open.

### 3. Sponsor Core Contributors Monthly
Allocate budget for ~12 core contributors. These aren't one-time payouts — they're monthly commitments that respect the ongoing work. Treat sponsorship as "partnership real estate."

### 4. Maintain a Rainy-Day Fund
Financial stability prevents burnout-driven decisions. Keep reserves so the project can weather slow sponsorship months without panic.

### 5. Release Early, Iterate Often
> "Get rid of your ego and just say here it is."

Publish incomplete work deliberately for community feedback. Don't wait for perfection. Ship alpha/beta versions, gather real-world usage data, iterate based on evidence.

### 6. Enforce Community Standards Firmly
Toxic members are not welcome. Maintain a code of conduct and enforce it. A healthy community attracts contributors; a toxic one drives them away.

---

## Philosophy

> "Maintaining an open source library is a lot like running a business, but with less risk."

Open source sustainability requires revenue, community management, and personal boundaries. Treat it as a business, not charity. Fund the maintainers, respect the contributors, and build something that outlasts any individual.
